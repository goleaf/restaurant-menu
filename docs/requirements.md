## Prompt 7 availability contract

- `sys-availability-001`: one class-based Livewire center has URL-backed Now, Schedules and Stop-list sections. Existing dashboard, waiter, settings and dish/menu entries open the correct restaurant/menu/item without another restaurant selector. Only the current section and bounded page are loaded; existing narrow settings/menu/availability permissions remain independent.
- A result carries stable reason codes/source, evaluation time, nearest condition change and conditional next orderable instant. Visibility, configuration feasibility and permission to accept a new order remain distinct. Displayed future evaluation is read-only and never enters a real order Action.
- Manual stop (`is_available`) and temporary public hiding (`hidden_until`) are independent. Each command changes exactly one source; expiry removes only the temporary condition. At least one available variant and enough available choices in every required modifier group must exist. Optional unavailable choices do not block the whole dish.
- Weekly intervals are local calendar rules with inclusive starts/exclusive ends and adjacent intervals joined. Overnight intervals belong to their starting day; closed-date exceptions override the entire chosen local date. Existing equal-endpoint menu records retain their historical full-day meaning; new ambiguous equal endpoints are rejected. DST-collapsed weekly occurrences are skipped; repeated-time boundaries use the earlier offset. One-off ambiguous or nonexistent local deadlines are rejected.
- Pause expiry, restaurant hours, menu hours and temporary hiding intersect; unknown or indefinite blockers have no fabricated reopening. Empty legacy hours/schedules mean no time restriction; all-days-closed is explicit. Copy-days only changes the unsaved draft and previews replacement.
- Pause, restaurant hours/date exceptions, menu schedules and dish restrictions have separate revisions. Preview binds relevant dependencies and timezone; fresh authorization and conflict checks run inside the mutation. UUID receipts identify the exact actor/scope/payload; replay neither extends a pause nor duplicates audit. Batch restrictions are atomic and page-scoped (20 selectable visible dishes; server maximum100).
- SQLite immediate write transactions serialize pause changes and final admission. A pause committed first prevents a concurrent stale new order. No cron, scheduler, worker, Redis, online stock system or future-order mechanism is required.
- All UI validation, reasons and confirmations use EN/LT/RU; local draft cancellation works offline and shared navigation guards preserve unsaved edits. The account guard rejects an old signed component after account replacement. Own SCSS uses existing tokens and the separate Tailwind/Flux CSS bridge.

## Unified dish card (Prompt 6)

- `sys-dish-001`: one directly routed class-based Livewire card owns the verified organization/brand/restaurant/dish context. Main, Photos, Variants and Modifiers have URL-backed sections; content language is separate from interface locale. The catalogue, content issues, copy result and legacy selected-item links enter that card. An unselected legacy variants link returns to the catalogue, never the first dish.
- Main details and EN/LT/RU translations save together. English is the server canonical name/description. Independent photo, variant and shared-group operations save explicitly without clearing main input; visited sections retain their drafts. Closing discards only unconfirmed input. No global Save All or automatic offline replay is permitted.
- Creation has no placeholder write. Explicit Create and continue creates one unavailable dish with a scoped UUID receipt; the saved card remains the destination.
