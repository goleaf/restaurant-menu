# Canonical requirements catalogue

## Status and interpretation

This is the only canonical active requirement catalogue. Stable identifiers must not be renumbered. Exact implementation, migration, translation, factory, test, command, and status evidence is recorded by the same identifier in `compliance-matrix.md`.

For the compact tables below, **control contract** combines authorization, validation, success, and failure behaviour. **Cross-cutting contract** combines security, data, localization, accessibility, and performance implications. Unless a row says otherwise, user-visible success and error text must exist in `en`, `lt`, and `ru`; controls must be keyboard/touch accessible; outputs must be escaped; and queries must be tenant-scoped, eager-loaded, and bounded.

## Functional requirements

|---|---|---|---|---|
| `sys-auth-001` | Public registration is disabled; invited staff can create an account through a valid invitation, then log in, log out, confirm passwords, and reset passwords. | Invited recipient, user / User, Invitation, session, reset token | Invitation registration validates recipient binding and atomically consumes the invitation; Fortify validates login/reset credentials; login regenerates session; logout invalidates session; reset tokens expire and cannot be reused. | Invite-only, rate-limited, CSRF protected, localized forms/errors, accessible focus/error association, generic failures. |

| `sys-tenant-001` | Organizations contain brands and branches; data never crosses organization or branch access boundaries. | Owner, director, admin, staff, superadmin / Organization, Brand, Branch | Active membership and subscription required; branch assignments narrow access; route relationships must match; superadmin bypass is explicit; wrong tenant is 403/404 without data. | Every query/cache key/export respects tenant and branch ownership. |

| `sys-branch-001` | Authorized users manage organization, brand, branch identity and public restaurant profile. | Owner/director/admin / Organization, Brand, Branch | Corresponding edit/manage permission and nested ownership; validated names, contact URLs, currency, timezone, and images; failures preserve input/files. | Public text is plain text; files local; lists paginated; soft deletes preserve history. |

| `sys-guest-001` | A guest can enter a free QR place or restore their table identity using an opaque cookie token without an account. | Guest / TableSession, TableSessionGuest | Name normalized/validated; QR/service point/branch/subscription state checked; only a digest/opaque secret grants restore; rejected/removed/closed guests cannot mutate. | Token hidden from HTML/logs; duplicate display names handled without treating names as identity. |
| `sys-guest-002` | Guests can invite others and approve/reject join requests for the same active table. | Active guest / invite token, JoinRequest, Guest | Same-session active guest required; token expires; duplicate requests are bounded/idempotent; approval/rejection atomic; closed/expired requests fail safely. | No internal ID disclosure; polling isolated; state changes announced accessibly. |
| `sys-menu-001` | Authorized users manage branch menus, categories, dishes, department assignment, availability, modifiers, and local images. | Menu manager, availability/price roles / Menu graph | Tenant/branch scope; permission split for CRUD, price, availability; strings, decimal price, nutrition, selections and image validated; soft delete preserves snapshots. | No float money; escaped/plain text; local images; growing lists bounded. |

| `sys-menu-003` | Guest-visible menus respect active status, branch timezone schedules, temporary closure, stock and modifier constraints. | Guest, waiter / MenuSchedule, MenuItem, Modifier | Server revalidates availability at every draft mutation; stale client attempts fail as localized domain conflicts; available menus remain ordered and grouped. | Cached payload is locale-scoped; no network API; query count bounded. |

| `sys-waiter-001` | Authorized waiters see branch/zone-scoped work, edit pending drafts, confirm/reject them, and open/transfer/merge tables safely. | Waiter, manager / dashboards, sessions, drafts | Every action checks current permission, branch assignment, resource state and action arguments; conflicts fail without partial writes. | Lists/payloads bounded; polling visible; no duplicate submissions; keyboard alternatives for any sorting. |
| `sys-order-001` | Waiter confirmation creates immutable order/item snapshots and explicit dispatch creates department tickets. | Waiter/manager / Order, OrderItem, KitchenTicket | `confirm_orders` and `send_to_departments`/compatible permission; transactions enforce one conversion/dispatch; stale/repeated calls are idempotent. | Money decimal-safe; snapshot history survives source deletion/change; guest sees localized progress. |
| `sys-department-001` | Authorized kitchen/bar staff see only accessible departments and advance ticket items through valid states. | Cook, chef, bartender / Department, Ticket, TicketItem | Department/branch access checked on mount and mutation; item id/status untrusted; cancelled/served/ready-invalid transitions blocked; updates synchronize aggregate state. | Oldest-first bounded polling; large touch targets; status uses text and color. |
| `sys-order-002` | Authorized staff can cancel eligible orders with a reason without deleting history. | Waiter/manager / Order, status/audit logs, tickets | `cancel_orders`; reason validation; transaction records previous/new state; cancelled tickets become non-actionable; repeated invalid transitions fail. | Guest-safe localized reason/state; no deletion; audit trail retained. |
| `sys-waiter-call-001` | Active guests can call a waiter or request the bill once per active state; authorized staff can acknowledge work. | Guest, waiter / WaiterCall, notifications, session | Active token/session checks; requests idempotent; staff tenant/permission checks; state transitions transactional. | Database notifications only; bounded polling; announced status and precise loading state. |
| `sys-payment-001` | Authorized staff record cash/card-terminal/other offline payments for a table or guest and close eligible sessions. | Cashier/accountant/manager / ManualPayment, Session | View/manage/close permissions separated; amount/tips/method/scope validated; balance locked/serialized against concurrent overpayment; duplicate submission safe. | Decimal/minor-unit arithmetic; immutable snapshots; audit log; no online provider. |

| `sys-subscription-001` | A local subscription status can disable ordinary organization access without affecting superadmin recovery. | Superadmin / OrganizationSubscription | Superadmin-only state change, confirmation/reason where dangerous, audit, valid enum/date; inactive access denied consistently. | No external billing; idempotent seeding; localized status. |
| `sys-superadmin-001` | Superadmin can inspect platform state and run bounded safety/cleanup operations. | Superadmin / organizations, safety report, cleanup | Explicit middleware/policy; maintenance actions lock and resume safely; no secret disclosure; failures are reported. | Growing lists cursor-paginated; operations work on shared hosting. |

## Non-functional and architecture requirements

| ID | Requirement | Roles / entities | Control contract | Cross-cutting contract |
|---|---|---|---|---|
| `sec-session-001` | Session, CSRF, origin, cookie, password, reset, passkey and 2FA controls follow current Laravel/Fortify defaults unless a stricter documented setting exists. | All users / auth state | HTTPS production cookies, HttpOnly, SameSite, regenerated login, invalidated logout, rate limits and expiring tokens are tested. | No weakening for tests; generic localized failures. |
| `sec-authz-001` | Every protected route, download, page and Livewire mutation performs server-side policy/gate authorization and tenant scoping. | Authenticated roles / all protected resources | Positive owner/role and negative non-owner/wrong-role/wrong-tenant/state tests; hidden UI is never the control. | Cache and serialization cannot bypass authorization. |
| `sec-input-001` | Every untrusted scalar, array, identifier, file, URL, locale, enum, date and monetary value is normalized and validated at the boundary. | All actors / all inputs | Only validated/explicit maps reach mass assignment; database constraints remain second defence; malicious/boundary cases tested. | Localized messages; no raw SQL/command/SSRF path. |
| `sec-output-001` | User content is plain text and escaped; raw HTML exists only behind a named, tested trusted renderer. | All viewers / text, QR SVG | Blade cannot call sanitizer/business services; rich content is rejected unless an explicit sanitizer contract is introduced. | CSP-compatible direction; XSS regression tests. |
| `sec-upload-001` | Local image/file lifecycle validates content and coordinates storage with persistence safely. | Authorized uploader / logos, covers, dishes, backups | MIME/content/size/dimensions, generated names, ownership, replacement compensation, authorized private downloads and cleanup tested. | No absolute paths, public private-file routes, S3, or internet fixtures. |
| `sec-dependency-001` | Production and development dependencies are stable, maintained, lock-file reproducible, and free of unresolved exploitable advisories. | Maintainers / Composer/npm graph | Stable releases only; `composer audit` and `npm audit` are release gates; exceptions require exact external blocker/review date. | One npm lock; no unnecessary package or paid runtime. |
| `data-schema-001` | Fresh and existing SQLite schemas preserve FK, unique, index, soft-delete and state invariants through reversible forward migrations. | Maintainers / all tables | Fresh migrate, rollback where meaningful, upgrade and foreign-key checks pass; no destructive production refresh/backfill. | Composite indexes follow query order; historical migrations are not rewritten after deployment. |
| `data-integrity-001` | Multi-record state transitions, token consumption, dispatch, payment and session movement are atomic, idempotent and race-safe. | All mutating roles / workflow aggregates | Transaction plus lock/unique/idempotency boundary; repeated/concurrent tests prove one valid result. | Side effects occur after commit or compensate. |
| `data-money-001` | Money is stored and calculated without binary floating-point error. | Guest/staff / prices, totals, payment snapshots | Decimal strings or integer minor units cross boundaries; precision/range/currency validated; rounding defined and tested. | Locale formatting is presentation-only and never affects stored value. |
| `perf-query-001` | Critical pages and polling blocks avoid N+1, unbounded reads and unnecessary hydration. | All viewers / query payloads | Explicit selects/eager loads, aggregates and pagination; reliable query-budget regression tests. | Locale switches do not trigger unrelated persistence reads; payloads bounded. |
| `perf-cache-001` | Each cache entry has explicit owner, scope, version, TTL and invalidation. | All tenants/locales / menu, dashboard, analytics, polling | Keys include tenant/branch/locale/permission context or cache neutral data; writes invalidate; locks prevent stampede. | Database cache only by default; no cross-context leaks. |
| `livewire-001` | All Livewire UI uses normal class components with separate Blade, minimal typed public state, authorized actions and intentional Livewire 4 features. | Interactive users / components | No Volt/SFC; identifiers locked where useful; inputs validated; polling/loading/offline/URL state precise; component tests cover direct invocation. | Accessible states, stable keys, bounded snapshots, no unnecessary `.live`. |
| `blade-001` | First-party Blade is presentation-only and contains no PHP blocks, models, queries, facades, services, container resolution or business transformations. | Maintainers / views | Automated repository test fails on forbidden constructs; prepared DTO/arrays/components replace logic. | Escaped output and translation keys only. |
| `tailwind-001` | Tailwind 4 uses CSS-first configuration, static source discovery and a coherent accessible design-token system. | All viewers / CSS/UI | Latest compatible packages, no unsafe dynamic utilities, production build required; mobile/desktop/forced-color/reduced-motion checks. | No Sass/Less; repeated arbitrary values become tokens. |
| `i18n-001` | `en`, `lt`, and `ru` remain complete through the single JSON localization system. | All users / UI, validation, notifications, SEO | Semantic keys, placeholder/plural parity, fallback tests, locale persistence, localized formatting; no hardcoded user text. | Cache locale separation and translated text expansion. |
| `ui-accessibility-001` | Critical workflows meet WCAG-oriented keyboard, screen-reader, touch, zoom, contrast, focus and reduced-motion expectations. | All users / auth, QR, order, operations | Semantic structure, labels/descriptions, field errors, announcements, modal focus trap/restore, minimum touch targets and automated/manual checks. | Native semantics preferred over redundant ARIA. |
| `ui-responsive-001` | Every data-driven interface has responsive loading, empty, error, offline, disabled, pending and success states without horizontal page overflow. | All users / UI surfaces | Test representative mobile/tablet/laptop/desktop widths; long/unbroken/localized text remains usable; duplicate actions disabled. | Mobile does not depend on hover; desktop remains keyboard accessible. |
| `seed-model-001` | Every first-party Eloquent model has a valid default factory and meaningful deterministic states. | Maintainers/test suite / 41 models | FK/unique/enum/date/money invariants hold; graph creation is explicit; every factory/state creation is tested. | No network or real personal data. |
| `seed-demo-001` | Fixed reference seeders are idempotent and demo seeding creates a realistic end-to-end restaurant only outside production. | Maintainers/demo users / roles, permissions, restaurant graph | Safe order, natural keys, no truncation; production refusal; repeated execution creates no duplicates; main pages render. | Fictitious data, documented non-production credentials, all roles/locales/states represented. |
| `test-feature-001` | Pest tests cover every first-party route and critical authentication, authorization, workflow, data, file, cache, locale and security branch. | Maintainers / test suite | Full suite passes; no assertion-free padding; regressions receive tests; critical state/auth branches have meaningful coverage. | Isolated SQLite and faked external I/O; parallel-safe when invoked. |
| `test-architecture-001` | Executable architecture checks enforce forbidden Blade/Volt/env/raw SQL/debug/dynamic-Tailwind/dependency patterns. | Maintainers / repository | Rule failures name exact files; exceptions are narrow and documented; Pint and Larastan pass without broad suppressions. | Coverage target is at least 90% meaningful application code when tooling can collect it. |
| `ops-deployment-001` | A production release is reproducible on PHP 8.5 shared hosting and provides migration, build, cache, filesystem, scheduler, health, rollback and backup guidance. | Operator / release | Composer/npm locked install, asset build, migrations, caches, storage link/alternative, `/up`, smoke test and rollback commands verified. | No runtime dependency on SSH-only workers, Redis, WebSockets, S3, Docker, or seeded demo credentials. |
